# Phase 1 調査・解析計画書（Phase 1 Research & Analysis Plan）

**プロジェクト**: 神奈川県廃墟調査プロジェクト（Kanagawa Ruins Research Project）  
**対象フェーズ**: Phase 1（歴史的遺構・廃神社候補の探索手法検証 PoC）  
**作成日**: 2026-10-09  
**初期対象地域**: 神奈川県相模原市緑区（旧津久井地域）  
- **青野原（あおのはら）**
- **青山（あおやま）**
- **鳥屋（とや）**
- **寸沢嵐（すあらし）**

---

## 1. 初期対象地域の選定背景と地理的特性

相模原市緑区の旧津久井地域は、道志川・相模川（相模湖）・串川および丹沢山地北縁に囲まれた山間急傾斜地と河岸段丘からなる地域である。
明治以降の近代化、昭和期の相模ダム建設（相模湖造成・寸沢嵐等の集落・農地水没）、昭和・平成期の林業衰退や過疎化、平成の大合併を経ており、以下のような歴史的変遷の痕跡が色濃く残る。

- **青野原**: 道志川沿いの集落と山間杣道。諏訪神社、八幡神社等の鎮座地。
- **青山**: 串川流域。青山神社（神輿のお浜降り伝統）、八坂神社、子ノ森神社。近世甲州街道脇往還の交通路。
- **鳥屋**: 丹沢北麓。県指定無形民俗文化財「鳥屋獅子舞」を伝える諏訪神社。明治期養蚕・林業の拠点。
- **寸沢嵐**: 相模川沿いの要衝。国指定史跡「寸沢嵐石器時代遺跡」、鼠坂八幡神社、日神社、天神社。相模ダム建設に伴う水没・集落移転と古道・旧社地の変遷。

本計画では、この4地区をパイロットエリア（PoC）とし、古地図・現代GIS・歴史的地誌を統合した廃神社・旧社地・古道探索パイプラインの成立性を検証する。

## 2. 検討項目

### (1) 解析可能な古地図の入手方法

古地図画像の解像度・幾何歪み・測量精度は記号検出と位置特定に直結する。以下の公的・研究アーカイブから合法的に入手する。

1. **迅速測図（農研機構 歴史的農業環境閲覧システム / 国立国会図書館）**:
   - 明治10年代（1880年代）に関東平野および周辺部で陸軍参謀本部陸軍部測量局により作成された彩色手描き地図。縮尺1/20,000。
   - 神奈川県北部・相模原市緑区周辺のカバー状況を確認。農研機構の利用条件（CC BY 2.1 JP）に基づき、タイルの一括無断取得を避け、対象地域の公式提供データを精査。
2. **国土地理院 旧版地形図（5万分の1 / 2万5千分の1）**:
   - 明治後期（大日本帝国陸地測量部）〜大正〜昭和戦前期の正式測量五千分一・二万五千分一・五万分一地形図。
   - 地図・空中写真閲覧サービスで索引・年代（図幅名: 吉野、中津川、上野原、八王子など）を確認し、正式な謄本交付・成果利用手続きを経て入手（解像度400〜600dpi TIFF）。
3. **今昔マップ on the web（埼玉大学 谷謙二研究室）**:
   - 利用規約に「画像ファイルのPC・サーバ等への保存禁止」が明記されているため、自動ダウンロードや機械学習入力には**一切使用しない**。検出結果のブラウザ目視照合（WebUI上での手動比較確認）にのみ限定する。

### (2) 歴史資料・神社台帳の取得方法

地図上の記号だけでなく、文字史料による裏付け（合祀・廃絶・遷座・水没の記録）を突き合わせる。

1. **近世官撰地誌**:
   - 『新編相模国風土記稿』（昌平坂学問所編、天保12年完成）：津久井県・愛甲郡の村ごとの神社・寺院・旧跡一覧。国立国会図書館デジタルコレクション（著作権保護期間満了・PD）より該当村（青野原村、青山村、鳥屋村、寸沢嵐村）の記述を抽出。
2. **近代行政・皇国地誌・郡誌**:
   - 『神奈川県皇国地誌草稿』（明治初期の神社明細帳・社寺台帳）
   - 『津久井郡誌』（大正14年、津久井郡役所編）：明治期の神社合祀令（一村一社政策）に伴う無格社・境内社・村社の合祀・移転・廃絶記録。
   - 『旧津久井町史』・『相模原市史』：昭和期のダム建設に伴う水没移転記録。
3. **現代宗教法人・文化財台帳**:
   - 神奈川県宗教法人名簿、神奈川県神社庁公開データ
   - 相模原市指定・登録文化財一覧（オープンデータ CSV）※参考データとして照合。

### (3) GISにおける座標系の統一

本プロジェクトで扱うデータは複数の異なる測地成果（CRS）に跨るため、推測変換を排除し、厳密な座標系パイプラインを組む。

- **統一採用CRS**: **JGD2011 / 平面直角座標系 第IX系 (EPSG:6677)**
  - 理由: 神奈川県・東京都を包含する国家標準の投影座標系であり、メートル単位での距離計算・バッファ処理・面積計測が高精度に行える。
- **入力ソース別変換設計**:
  - 住居表示住所（`gsi_jusho_midori`）: JGD2000/2011 緯度経度 (EPSG:4612 / EPSG:6668) → EPSG:6677
  - 国土数値情報行政区域（`MLIT-N03`）: JGD2011 緯度経度 (EPSG:6668) → EPSG:6677
  - 基盤地図情報 DEM/道路網（`GSI-FGD`）: 2026年移行分はJGD2024 (EPSG:10249等) → 国土地理院パラメータ変換式（TKY2JGD / JGD2024変換パラメータ）に基づく厳密変換 → EPSG:6677
  - 古地図ラスタ（オルソ補正後）: GCP補正時に直接 EPSG:6677 の投影座標系 GeoTIFF として出力。

### (4) 既知神社・旧社地の正解データ（Ground Truth）作成

モデルの評価および誤検出防止のため、初期対象4地区の「現存神社」「既知合祀旧社地」「指定文化財」の教師データセットを構築する。

1. **現存神社アノテーション**:
   - 神奈川県神社庁データおよび現地字名・登記・現代地形図に基づき、4地区の現存神社（青野原諏訪神社、青山神社、鳥屋諏訪神社、鼠坂八幡神社等）の正確な境内ポリゴンおよび鳥居位置ポイントを作成。
2. **合祀・旧社地データ**:
   - 『津久井郡誌』等の文献に記載された「明治期に合祀された旧社地」の字名・推定位置を特定。
3. **属性定義**:
   - `shrine_id`, `name`, `status` (existing / merged_former_site / unknown), `historic_source`, `current_status_source`, `geometry`

### (5) 古地図の位置合わせ（ジオリファレンス）方法

古地図（特に明治前期の迅速測図や初期地形図）は現代の正射投影と異なり局所的な紙の歪み・測量誤差を含む。

1. **コントロールポイント（GCP）選定基準**:
   - 三角点（一等・二等・三等三角点）の不動点
   - 古代・近世から流路が変わっていない岩盤部の河川合流点（道志川・相模川の峡谷部）
   - 古道・往還の石造物（庚申塔・道標）および近世寺社境内の位置
   - 鉄道・ダム建設等による改変箇所（相模湖湖畔等）はGCPから除外
2. **幾何補正アルゴリズム**:
   - 単純アフィン変換（1次多項式）では局所歪みに追従できないため、**薄板スプライン法（Thin Plate Spline: TPS）** または **局所2次多項式変換（Polynomial 2）** を採用。
   - GDALの `gdal_translate` (GCP付与) → `gdalwarp -tps -r bilinear -t_srs EPSG:6677` パイプラインをCLIスクリプト化。

### (6) 鳥居記号の検出方法

古地図ラスタから「⛩」（鳥居）記号を検出する手法として、段階的アプローチを検討する。

1. **Phase 1 初期 PoC: テンプレートマッチング＋形態素フィルタ**:
   - OpenCVの `cv2.matchTemplate`（正規化相互相関 `TM_CCOEFF_NORMED`）。
   - スケール変化（縮尺差）・回転（古地図の文字配置）に対応するため、複数スケール・微小回転（-15°〜+15°）の鳥居テンプレート群を用意。
   - 二値化（適応的閾値処理）および細線化処理を前処理として適用。
2. **発展手法: 深層学習物体検出（YOLOv8 / DETR）**:
   - 古地図の紙焼け、等高線・文字・ハッチングとの交差ノイズに対応するため、YOLOv8（Nano/Small）等の軽量物体検出モデルの適用を検討。
   - 教師データ不足に対しては、合成データ生成（現代地図ベクター記号の古地図風背景への合成配置）を活用（参考文献参照）。

### (7) 検出精度の評価方法

1. **定量的評価指標**:
   - **適合率 (Precision)**: 検出された鳥居候補のうち、真の鳥居（現存神社または古社地）の割合。
   - **再現率 (Recall)**: 正解データ（Ground Truth）に存在する鳥居のうち、検出できた割合。
   - **F1-score**: 適合率と再現率の調和平均。
   - **IoU (Intersection over Union)**: バウンディングボックスの重なり評価（IoU >= 0.5）。
2. **偽陽性（False Positive）要因の分類とフィルタリング**:
   - 記号類似ノイズ: 墓地記号「+」、測量点記号、文字の部首（木、林、柱など）、等高線の交差。
   - フィルタリングルール: 現代道路網バッファ、住居表示字名・現役市街地対照、標高勾配（極端な絶壁・河川中央の除外）。
3. **倫理的検証プロセス**:
   - 「現地非侵入（No Field Trespassing）」の原則を厳守。現地調査を行わず、航空写真（年代別オルソ）、登記公図、自治体史、航空レーザ測量DEM（微地形立体図）の遠隔照合で確からしさを判定。

### (8) Google Drive上での大容量データ管理

ローカルPCストレージの1GB一時ファイル制限を遵守し、Google Drive側（`$RUINS_DATA_ROOT`）で大容量データを効率的に運用する。

1. **ディレクトリ構造設計**:
   ```text
   kanagawa_ruins_search_databank/data/
   ├── raw/                      # 一次データ原本（読み取り専用・不変）
   │   ├── maps_historical/      # 古地図高精細TIFF
   │   ├── dem_fgd/              # 基盤地図情報DEM
   │   └── text_archives/        # 地誌史料・翻刻テキスト
   ├── processed/                # 前処理済み派生データ
   │   ├── georeferenced/        # TPS補正済みGeoTIFF (EPSG:6677)
   │   ├── ground_truth/         # 正解データGeoPackage / GeoJSON
   │   └── tiles/                # 解析用タイルスライス (512x512)
   ├── models/                   # 学習済み重み・テンプレート
   └── provenance.jsonl          # 全データの取得・生成来歴
   ```
2. **タイリングとメモリ制約管理**:
   - 数GBに及ぶ巨大古地図GeoTIFFを直接メモリに読み込まず、`rasterio.windows` または `gdal_retile` を用いて 512×512 〜 1024×1024 のタイルにストリーミング分割処理。
   - ローカルPC上の一時キャッシュは処理バッチごとに即時パージし、常時1GB以内を維持。
