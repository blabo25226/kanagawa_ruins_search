# Rule 40 — 再現性と品質管理

- `git diff --check`、ユニットテスト、環境チェックを実行。
- 成功と失敗を分け、未実施を未実施と記載する。環境・バージョン・コマンドを残す。
- データ取得: ZIP/CSVの基本形式・サイズ・SHA-256を検証。Phase 1-AではGIS変換・検索基盤の検証に必要な内容の読み込みのみ許可。
- `data/raw`は不変原本とし、後で処理する場合は`data/processed`へ出力する。
- 重複ダウンロード、既存データの上書き、破壊的なGit操作を避ける。
- 元サイトの更新やURL変化があれば修正内容と検証結果をレビュー対象にする。
