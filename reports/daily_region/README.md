# 地域別デイリー分析（R1〜R7 循環）

ユーザーの明示指示（2026-10-26）により開始した、継続分析シリーズ。
成果物はすべてこのブランチ `analysis/daily-region-cycle` に集約する（main へは push しない）。

## ローテーション

- 開始日 2026-10-26 を Day 1 とし、毎日1地域を対象にする。
- 順番は R1 → R2 → R3 → R4 → R5 → R6 → R7 → R1 → …（7日で一周、8日目が次の週の R1）。
- 地域の定義は `config/phase1c2_regions.toml` の R1〜R7 に従う。
  - R1 横浜・川崎 / R2 三浦半島 / R3 湘南 / R4 県央（相模原市を除く） /
    R5 相模原（旧津久井郡を除く） / R6 津久井（旧津久井郡4町） / R7 県西
- 週数は `floor((経過日数) / 7) + 1`、週内の地域は `経過日数 mod 7` で決める。

## 各回の構成（固定）

1. **現在分析できていること** — 対象地域についてリポジトリの既存成果（主に Phase 1-C2 v0.2.0 の
   集計、Phase 1-C1 の実施範囲）で言える範囲と、言えない範囲（網羅率・scope）を最初に固定する。
2. **周知の事実・地域の特徴** — 公的資料・報道などのウェブ検索で裏付け、出所 URL を残す。
3. **仮説** — 検証前に、支持／棄却の目安となる閾値を文章で明示する。
4. **分析** — リポジトリの集計データ（`reports/phase1c2_results.json` 等）を再計算して検証する。
   再計算スクリプトを `scripts/` に同梱し、レポートの数値はスクリプトで再現できるものだけを使う。
   ウェブで得た数値は出典と対象期間を明記し、期間の違うデータを因果でつながない。
5. **結果と考察** — 仮説の支持／棄却／保留を分け、廃墟調査（本プロジェクトの目的）への含意と
   限界（判読法の変更、1セル成分の多さ、重心帰属など）を書く。
6. **反省点** — 主に分析・調査の進め方について、翌日に引き継ぐ改善点を具体的に書く。

## 継続のルール

- **2日目以降**: 前日のレポートの「反省点」を最初に読み、少なくとも1つをその日の分析に反映し、
  反映した旨をレポートに明記する。
- **2週目以降**: 前日に加えて、先週の同地域レポートの「結果・考察」と「来週への宿題」を読み、
  先週の仮説の続編・再検証・未解決事項の引き継ぎを必ず1件以上行う。
- 反省の累積は `reflections_log.md` にも1行ずつ追記する（上書きしない）。
- **各回の push 後、その日のレポートの要約を PR #28 のコメントとして投稿する**（ユーザー指示 2026-10-26）。
  要約には対象地域と週、仮説と判定、核心の数値、反映した反省、レポートへのリンクを含める。

## 境界（フェーズゲートとの関係）

ユーザー指示（2026-11-05）により、この節の以前の禁止（候補地点を出さない、座標を扱わない、
新規取得をしない、Drive を読まない）は次の運用に置き換える。

- 消失候補の直接探索を各回に含める。
- ユーザーの Drive データは読み取りだけに使う。台帳の原本は書き換えない。
- 公開データは新たに取得してよい。取得元 URL・取得日・ライセンスを記録する。
  旧版地図・今昔マップ・迅速測図のタイル一括取得は、Drive の
  `data/raw/historical_maps/README.md` の制約に従い行わない。
- 正確な緯度経度、地点を特定できる名称、大字以下の住所、候補一覧 CSV、
  その他公にすべきでない情報は、リポジトリに置かない。非公開の内部資料に記録する。
  リポジトリでは候補 ID と市区町村名だけを参照する。
- 新規取得した公開データの実体もリポジトリに置かない。
- 既存の過去レポートは上書きしない。成果物は `reports/daily_region/` 配下に新規追加する。
- main には push しない。PR #28 はマージしない。
